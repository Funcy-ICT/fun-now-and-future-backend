# ハード（ESP32）担当のやること

ハード担当が最初に読むもの。プロジェクトの概要、担当する作業、決まっていないこと（担当者に確認すること）をまとめる。
全体の構成は[docs/overview.md](../docs/overview.md)、バックエンドからの依頼の原文は[#35](https://github.com/Funcy-ICT/fun-now-and-future-backend/issues/35)。

## プロジェクトの概要

キャンパス（食堂やバス停など）の混雑度を、サイネージに出すシステム「Fun Now and Future」。

```
ESP32（ハード）──1分ごとにPOST──▶ バックエンド（Cloud Run）──▶ サイネージ（フロント）
  周りのBLE端末を検出              5分ごとに台数を数え、混雑度1〜9を出す
```

担当は、バックエンド（このリポジトリの`cloud/`）、フロント（サイネージ）、ハード（ESP32のファームウェア）に分かれている。

## 担当する作業

### 1. 基本の動き
- NimBLEで周りのBLE端末をスキャンし、1分ごとに`POST /receiveSensorData`へJSONを送る。ヘッダに`x-api-key`を付ける
- 送る形は[sensor_data.ts](../cloud/src/schema/sensor_data.ts)、またはSwagger（`/ui`）で見る

```json
{
  "sendId": "UUID",
  "nodeId": "esp32_cafeteria_01",
  "location": "cafeteria",
  "devices": [
    { "format": "raw", "mac": "AA:BB:CC:DD:EE:01", "rssi": -60, "rawData": "02011a..." }
  ]
}
```

- 検出が0件でも`devices: []`で送る。何も届かないと、ノードが止まったのと区別できないため
- 1回の送信は256台まで。RSSIは-127〜20。範囲外や不正なMACが1件でもあると、POST全体が400になる
- 応答は200（受け付けた）、400（ボディが不正。再送しない）、401（APIキーが無い、または違う）、500（サーバー側の失敗。再送する）

### 2. バックエンドからの依頼（#35）
- [ ] 送信ごとに一意なUUIDを付ける（`sendId`）。再送のときは同じUUIDを使う。重複の排除に使う
- [ ] ノードごとのAPIキーを、ヘッダに付ける。今は1つのキーを共有している
- [ ] 4xxは再送しない。400はデータが不正なときで、再送しても通らない
- [ ] 5xxやネットワーク障害のときは、間隔を空けて再送し、送れなかった分をメモリにためる。ためる量には上限を決める
- [ ] 応答が小さくなる（`status`、`sendId`、`received_at`くらい）。応答をパースしている箇所があれば確認する
- [ ] 送信のタイミングを、ノードごとに少しずらす
- [ ] サーバー証明書の検証を切らない（`setInsecure()`を使わない）
- [ ] MACの書式を常に同じにする（区切り文字、大文字小文字、並び順）。将来のLoRaの経路（`parsed`）とも揃える
- [ ] `raw`での送信を続ける。`rawData`をBigQueryに残すため
- [ ] 送信は1分ごと（約10ノード）。TLSの接続は使い回す（keep-alive）
- [ ] NimBLEのアドレス種別（public / random）が送れるなら、追加する。送れれば、サーバーでの推定より優先する

将来の候補: 観測時刻（NTPで合わせた時刻、または`millis()`の差）。滞在時間や「k回以上」の判定に使える。

完了条件: 上の項目のうち、対応する項目とその時期を、担当者（#35の起票者: chirushiyo）と合意している。

### ハードの構成
4. LoRaの経路。[dataSheet/](dataSheet/)にRaspberry Pi 4とLoRaモジュール（E220-900T22S）のデータシートがあるが、設計の文書が無い。Wi-Fiの無い場所で使うのか、ラズパイを中継（ゲートウェイ）にするのか、いつ入れるのか。コードには「LoRaでは`parsed`で送る。フィルタでの扱いは導入時に決める」とだけある

6. 設置場所のWi-Fi（どのネットワークか、eduroamのような企業認証か）、電源、ケース

### 通信
7. 送信先のURL。まだデプロイしていない（[#57](https://github.com/Funcy-ICT/fun-now-and-future-backend/issues/57)）。それまではローカルのサーバーで試す（[README](../README.md)の「ローカルで動かす」）

10. 証明書の検証に使うルートCA（どれを埋め込むか、期限切れへの対応）

### データの形
11. MACのバイトの並び順。サーバーは先頭のバイトを最上位として、アドレス種別を推定している（[mac.ts](../cloud/src/services/mac.ts)）。NimBLEが出す順と合っているか、実機のデータで確かめる
12. アドレス種別を送るときのフィールド名と値。今のスキーマには無い
13. スキャンの設定（アクティブかパッシブか、スキャンの時間）。文書に無い
14. 観測時刻（将来の候補）をやるか、いつやるか
