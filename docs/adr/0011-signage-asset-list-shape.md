# 0011. 広報アセットの一覧に、タグと説明を足し、ファイルのURLと種類をmediaにまとめる

- ステータス: 一部をADR 0018で置き換え（決定3の`contentType`の値）
- 決定日: 2026-10-15
- 起票: chirushiyo
- 関連: #64, #56, #20, ADR 0006（決定3の返す項目と、`prAssets`のスキーマを置き換える）

## 背景

ADR 0006では、`GET /signage/assets`が返す項目を、ID、題名、種類、URL、掲載終了日時とした。サイネージのフロントエンドが表示する項目は、タグ、題名、説明、画像で、返す項目と合っていなかった（#64）。タグと説明は、Firestoreの`prAssets`にも無かった。

`contentType`は自由な文字列で、画像かPDFが入る想定だった。フロントエンドは、種類によって表示の仕方を分ける必要がある。PDFを表示するかどうかは、まだ決まっていない（#56）。

まだ運用しておらず、`prAssets`に移行の必要なドキュメントは無い。

## 決定

1. Firestoreの`prAssets`と、一覧の各要素に、`tag`と`description`を足す。`tag`は空でない文字列、`description`は空の文字列も許す
2. ファイルのURLと種類は、各要素の`media`にまとめる。各要素は`id`、`tag`、`title`、`description`、`media`（`url`、`contentType`）、`publishUntil`とする
3. `contentType`は、`image/jpeg`、`image/png`、`application/pdf`のどれかに限る。値の一覧は`PR_ASSET_CONTENT_TYPES`の1か所に置き、Firestoreの検証と返す形の両方で使う
4. `id`は残し、`media`の外に置く
5. 一覧は、今までどおり配列で返す
6. 足したフィールドは必須とし、既存のドキュメントは移行しない

## 理由

- `media`にまとめる: `url`と`contentType`は表示するファイルの情報で、`tag`、`title`、`description`は掲示物の内容の情報。まとめると、フロントエンドは`media`を表示の部品にそのまま渡せる
- 種類が増えたときに変わる範囲を狭める: 動画などを足すときに変わるのは、`media`の中と、フロントエンドの表示の分岐だけになる。種類ごとに必要な情報が違ってきたら（動画の再生時間、PDFのサムネイルなど）、`media`を`contentType`で切り替える形（判別共用体）にする。上の階層は変わらない
- `contentType`を決まった値にする: SwaggerとHono RPCの型に、取りうる値が出る。フロントエンドは、表示の分岐の書き漏れを型で確かめられる。想定外の種類のドキュメントは、検証で一覧から外れる
- `id`を`media`の外に置く: `id`はファイルではなく掲示物を指す。フロントエンドの表示には出ないが、一覧を描画するときのキーと、同じ掲示物かを見分けるのに使う
- 配列のまま返す: サイネージは一覧を順に表示するので、順番に意味がある。JSONのオブジェクトは、キーの順番を保証しない。`GET /getCongestionHistory`も配列で返している
- 必須にする: 運用前で、移行の必要なドキュメントが無いため

## 検討した選択肢

| **選択肢** | **採用しなかった理由** |
|---|---|
| 一覧を、`id`をキーにしたオブジェクトで返す | 表示の順番をAPIで保証できない。サイネージは全件を順に描画するだけで、`id`で1件を引く場面が無い。OpenAPIでは`additionalProperties`になり、型が読みにくい |
| `url`と`contentType`を、今までどおり各要素の直下に置く | 掲示物の項目とファイルの項目が混ざる。種類ごとに必要な情報が増えると、上の階層の形が種類によって変わる |
| `id`を外す（フロントエンドが表示しないため） | 描画のキーと、同じ掲示物かの判定に要る。URLの末尾から切り出させると、URLの形に依存する |
| 画像の実体を一覧に含める（フロントエンドの`image`に合わせる） | ADR 0006で採用しなかった理由のまま。実体は公開バケットから直接取得する |
| `media`を最初から配列にする（1件に複数のファイル） | Firestoreの設計が`objects/{id}`で、1件につき1ファイル。必要になったときに、Firestoreの設計と一緒に変える |
| `contentType`を自由な文字列のままにする | 表示を分けるための値が型に出ない。想定外の種類が一覧に混ざる |
| 足したフィールドを任意（optional）にする | 移行するドキュメントが無い。任意にすると、フロントエンドが値の無い場合を扱う必要が残る |

## 結果

- 返す形が変わるので、ADR 0006の形で書いたクライアントは動かない。フロントエンドの通信はまだできていないので（#64）、影響は無い
- `PR_ASSET_CONTENT_TYPES`に無い種類（GIF、動画など）は、Firestoreに入れても一覧に出ない。増やすときは、`PR_ASSET_CONTENT_TYPES`に足し、フロントエンドの表示も分ける
- 検証に通らないドキュメントは、ログを出して一覧から外れる（`getApprovedPrAssets`）。`tag`か`description`の無いドキュメントも一覧に出ないので、手で入れるときに気をつける
- 1件に複数のファイルを付けるときは、`media`を配列に変える。返す形を壊す変更になる

## 残っている課題

- `tag`の値: 自由な文字列か、決まった値か。1件に1つか、複数か。今は空でない文字列としている
- `description`の長さの上限。今は上限が無い
- PDFの表示: 表示するかどうかと、その方法（#56）。pdf.jsなどで読み込むなら、公開バケットにCORSの設定が要る。表示しないなら、`PR_ASSET_CONTENT_TYPES`から外す
