# 0018. 広報アセットは画像だけにし、タグは1件に1つにする

- ステータス: 採用
- 決定日: 2026-10-19
- 起票: chirushiyo
- 関連: #56, #64, ADR 0011（決定3の`contentType`の値を置き換え、「残っている課題」のうち、PDFの表示と、タグの数を決める）

## 背景

ADR 0011では、`contentType`を`image/jpeg`、`image/png`、`application/pdf`のどれかに限った。PDFを表示するかどうかは決まっておらず、表示しないなら`PR_ASSET_CONTENT_TYPES`から外す、としていた（#56）。

PDFを表示するには、pdf.jsなどで読み込む必要があり、公開バケットにCORSの設定も要る。画像は、返ってきたURLを`<img>`でそのまま読める（ADR 0006）。

`tag`は空でない文字列としていたが、1件に1つか複数かは決まっていなかった。

## 決定

1. `PR_ASSET_CONTENT_TYPES`を`image/jpeg`と`image/png`にし、PDFを外す。`media.contentType`は返す形に残す
2. `tag`は1件に1つとし、今までどおり文字列で持つ

## 理由

- PDFを外す: サイネージは掲示物を画像として表示する。PDFを表示する仕組みと、バケットのCORSの設定を持たずに済む。PDFの掲示物は、画像にしてから登録すればよい
- `contentType`を残す: Firestoreに入れるファイルの種類を検証するのに使う。動画などを足すときに、返す形を壊さずに済む（ADR 0011の理由のまま）
- タグを1つにする: 返す形とFirestoreのスキーマが、今の形のままでよい。複数にするなら、配列に変える（返す形を壊す変更になる）

## 検討した選択肢

| **選択肢** | **採用しなかった理由** |
|---|---|
| PDFを残し、pdf.jsなどで表示する | 表示の仕組みと、公開バケットのCORSの設定が要る。画像にしてから登録すれば足りる |
| `contentType`を返す形から外し、`media`を`url`だけにする | 画像しか無いので、今は表示の分岐が要らない。ただ、種類を足すときに返す形が変わる。Firestoreの検証には、どのみち要る |
| タグを配列にする（1件に複数） | 今は複数のタグを使う場面が無い |

## 結果

- `contentType`が`application/pdf`のドキュメントは、検証で一覧から外れる（ログが出る）。PDFは画像にしてから登録する
- サイネージのフロントエンドは、`media.contentType`で表示を分けずに、`<img>`で読めばよい
- 1件に複数のタグを付けたくなったら、`tag`を配列に変える。返す形を壊す変更になる

## 残っている課題

- `tag`の値: 自由な文字列か、決まった値か
- `description`の長さの上限。今は上限が無い

## 実装

- `df42738` `PR_ASSET_CONTENT_TYPES`からPDFを外し、Swaggerの説明を直し、PDFが一覧に出ないかのテストを足した
